# backend_llm_dsl

Thesis prototype for comparing LLM-to-NestJS generation pipelines. The canonical intermediate representation is a YAML blueprint dictionary.

## Architecture

- Natural language -> LLM -> YAML blueprint -> NestJS generator.
- Natural language -> LLM -> textual DSL -> lexer/parser -> AST -> resolver -> YAML blueprint -> NestJS generator.
- Raw and mixed baselines produce a JSON file map directly or with blueprint context.

## Packages

`apps/cli` contains the `nestforge` CLI. `apps/experiments` contains experiment orchestration and analytics. Core code lives in `packages/blueprint`, `packages/dsl_core`, `packages/generator_nestjs`, `packages/llm_providers`, `packages/shared`, and `packages/validator`.

## Textual DSL MVP

Supported declarations are `app`, `enum`, `entity`, primitive fields, relation annotations, field validation annotations, and `module <ModuleName> for <EntityName>`. Primitive types are `string`, `number`, `boolean`, and `date`. Routes and DTOs are generated by convention from entity definitions. The textual DSL does not support arbitrary route, DTO, or custom type customization in the MVP.

## Prompt variants

Final textual ablation approaches are `textual-gen-baseline`, `textual-gen-spec`, and `textual-gen-fewshot`. Each has a separate prompt version, prompt hash, result label, and artifact path.

## CLI

```bash
pip install -e .
nestforge compile examples/textual_dsl/simple.dsl --output blueprint.yaml
nestforge validate examples/textual_dsl/simple.dsl
nestforge generate-file examples/textual_dsl/simple.dsl --output generated/
nestforge generate-prompt "Create a blog API" --approach dsl --provider openrouter --model openai/gpt-oss-20b:free
nestforge experiments run --approach all --provider openrouter --repetitions 1
nestforge experiments export
```

## Experiment artifacts

Timestamped runs are authoritative under `results/runs/<run-id>/`. Each case, approach, and repetition writes `record.json`, `requirement.txt`, generation artifacts, `generated-project/`, `validation.json`, `judge.json`, and logs under `cases/<case-id>/<approach>/rep-<n>/`.
